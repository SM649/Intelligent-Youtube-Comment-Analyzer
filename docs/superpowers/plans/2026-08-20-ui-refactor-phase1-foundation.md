# UI Refactor Phase 1: Tailwind Toolchain + Base Layouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the Tailwind CLI toolchain and the two shared Jinja base layouts
(`base_public.html`, `base_dashboard.html`) with their navbar/footer/flash partials, and prove
both work end-to-end by migrating the two simplest pages (`about.html`, `History_model.html`)
off Bootstrap onto them.

**Architecture:** Tailwind compiled via the standalone CLI (no Node/npm) from a checked-in
`tailwind.config.js` + `static/tailwind-input.css`, output committed to `static/tailwind.css`.
Two Jinja base layouts replace the 7 templates' current copy-pasted `<head>`/navbar/footer.
Alpine.js (CDN) replaces the two bits of interactivity that genuinely depended on Bootstrap's
JS bundle (mobile nav toggle, profile dropdown); the sidebar collapse/expand keeps its existing
vanilla-JS toggle in `static/myjs.js` unchanged, since that never depended on Bootstrap.

**Tech Stack:** Flask 2.x + Jinja2 (existing), Tailwind CSS v3 standalone CLI, Alpine.js v3
(CDN), Font Awesome 6 + Bootstrap Icons (CDN, unchanged), AOS 2.3.4 (CDN, unchanged).

**Spec:** `docs/superpowers/specs/2026-08-20-ui-refactor-design.md`

## Global Constraints

- No Node/npm, no `package.json` — Tailwind is compiled by its standalone CLI binary only.
- **Tailwind CSS v3** (not v4) — pin to the standalone CLI release `v3.4.17` from
  `https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/`. v3 keeps the
  classic `tailwind.config.js` + `@tailwind base/components/utilities` model already committed
  to in the spec; v4's CSS-first `@theme`-block config is a different (and larger) convention
  change that was never proposed to the user.
- Bootstrap CSS **and** JS are being removed page-by-page as each template migrates — a
  template only stops loading Bootstrap once it fully extends one of the two new base layouts.
  Do not remove the Bootstrap `<link>`/`<script>` tags from templates this plan does not touch.
- Font Awesome 6, Bootstrap Icons, and AOS 2.3.4 all stay, unchanged, on every page.
- `static/tailwind.css` is committed to the repo (so `python app.py` works locally with zero
  setup) and is regenerated fresh at Docker build time.
- This plan does **not** touch `landing.html`, `login.html`, `register.html`, `index.html`,
  `profile_settings.html`, `auth.py`, or the old `auth.css`/`dashboard.css`/`pages.css` files —
  those are Phase 2 (a separate plan), because they still depend on the old standalone
  templates/CSS files until migrated. Do not delete `auth.css`/`dashboard.css`/`pages.css` in
  this plan.

## File Structure

**Create:**
- `tailwind.config.js` — theme tokens ported from the existing CSS custom properties.
- `static/tailwind-input.css` — Tailwind entry file.
- `static/tailwind.css` — compiled output (committed).

- `templates/base_public.html` — layout for landing/about/login/register.
- `templates/base_dashboard.html` — layout for index/History/profile settings.

- `templates/_navbar_dashboard.html` — dashboard sidebar partial.

- `templates/_flash.html` — flash-message partial (renders `get_flashed_messages`).

**Modify:**

- `.gitignore` — add `.tailwindcss-cli`.
- `templates/about.html` — rewritten to `{% extends "base_public.html" %}`.
- `templates/History_model.html` — rewritten to `{% extends "base_dashboard.html" %}`.

- [ ] **Step 4: Write `scripts/tailwind-watch.sh`**

```bash
#!/usr/bin/env bash
set -euo pipefail

CLI_VERSION="v3.4.17"
CLI_PATH="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)/.tailwindcss-cli"
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"

if [ ! -x "$CLI_PATH" ]; then
  OS="$(uname -s)"
  ARCH="$(uname -m)"
  case "$OS-$ARCH" in
    Linux-x86_64) ASSET="tailwindcss-linux-x64" ;;
    Linux-aarch64) ASSET="tailwindcss-linux-arm64" ;;
    Darwin-x86_64) ASSET="tailwindcss-macos-x64" ;;
    Darwin-arm64) ASSET="tailwindcss-macos-arm64" ;;
    *)
      echo "Unsupported platform: $OS-$ARCH. Download the CLI manually from" >&2
      echo "https://github.com/tailwindlabs/tailwindcss/releases/tag/$CLI_VERSION" >&2
      echo "and save it as $CLI_PATH" >&2
      exit 1
      ;;
  esac
  echo "Downloading Tailwind CLI $CLI_VERSION ($ASSET)..."
  curl -sSL -o "$CLI_PATH" \
    "https://github.com/tailwindlabs/tailwindcss/releases/download/$CLI_VERSION/$ASSET"
  chmod +x "$CLI_PATH"
fi

"$CLI_PATH" \
  -i "$REPO_ROOT/static/tailwind-input.css" \
  -o "$REPO_ROOT/static/tailwind.css" \
  --config "$REPO_ROOT/tailwind.config.js" \
  --watch
```

- [ ] **Step 5: Make the script executable and run a one-shot build (not watch) to produce the initial `static/tailwind.css`**

Run:
```bash
chmod +x scripts/tailwind-watch.sh
OS="$(uname -s)"; ARCH="$(uname -m)"
case "$OS-$ARCH" in
  Linux-x86_64) ASSET="tailwindcss-linux-x64" ;;
  Linux-aarch64) ASSET="tailwindcss-linux-arm64" ;;
  Darwin-x86_64) ASSET="tailwindcss-macos-x64" ;;
  Darwin-arm64) ASSET="tailwindcss-macos-arm64" ;;
esac
curl -sSL -o .tailwindcss-cli \
  "https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/$ASSET"
chmod +x .tailwindcss-cli
./.tailwindcss-cli -i static/tailwind-input.css -o static/tailwind.css --config tailwind.config.js --minify
```

Expected: `static/tailwind.css` is created and non-empty (a minified Tailwind base+utilities
stylesheet, several hundred KB uncompressed rule set minified down — the exact size depends on
what `content` finds referenced in `templates/**/*.html`, which is still all-Bootstrap markup
at this point, so the file will be small until Tasks 6/9 add Tailwind classes to templates).

### Task 2: Regenerate Tailwind CSS at Docker build time

**Files:**
- Modify: `Dockerfile`

**Interfaces:**
- Consumes: `tailwind.config.js`, `static/tailwind-input.css` (Task 1).
- Produces: a freshly-regenerated `static/tailwind.css` inside the built image, so the
  deployed CSS always matches the deployed templates/config even if the committed file drifts.

- [ ] **Step 1: Add a `RUN` step after the app code is copied in, before the final `CMD`**

In `Dockerfile`, insert this block between the existing `COPY --chown=user . .` line and the
`ENV PORT=7860` line:

```dockerfile
COPY --chown=user . .

RUN python3 -c "import urllib.request; urllib.request.urlretrieve('https://github.com/tailwindlabs/tailwindcss/releases/download/v3.4.17/tailwindcss-linux-x64', 'tailwindcss-cli')" \
    && chmod +x tailwindcss-cli \
    && ./tailwindcss-cli -i static/tailwind-input.css -o static/tailwind.css --config tailwind.config.js --minify \
    && rm tailwindcss-cli

ENV PORT=7860
```

(`tailwindcss-linux-x64` is hardcoded here, not the multi-platform detection from
`scripts/tailwind-watch.sh`, because the Docker build always runs on `linux/amd64` — Hugging
Face Spaces' Docker Space build environment.)

- [ ] **Step 2: Verify the Dockerfile still parses and the new step is well-formed**

Run: `docker build --no-cache -t yt-analyzer-tailwind-check .`

If Docker isn't available/desired locally, at minimum run:

assert content.index('COPY --chown=user . .') < content.index('tailwindcss-cli')

        const card = this.closest('.video-card');
        if (!card) {
          console.error('Could not find .video-card parent');
          return;
        }

        if (!confirm('Are you sure you want to delete this Analyses?')) {
          return;
        }

        fetch(`/delete_history/${videoId}`, {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' }
        })
          .then(res => res.json())
          .then(data => {
            if (data.success) {
              card.remove();
            } else {
              alert('Failed to delete: ' + data.message);
            }
          })
          .catch(err => {
            console.error('Error deleting history:', err);
            alert('An error occurred.');
          });
      });
    });
  });
</script>
